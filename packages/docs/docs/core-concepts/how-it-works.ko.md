# Panacea 작동 방식

Panacea는 **에이전트 루프**를 실행합니다: 프롬프트를 읽고, 호출할 도구를 결정하고, 실행하고, 결과를 읽고, 반복합니다 — 추론과 편집 내용을 스트리밍으로 다시 보여주며 — 작업이 완료되거나 턴 제한에 도달할 때까지 계속됩니다.

## 도구

기본적으로 Panacea의 에이전트는 다음을 호출할 수 있습니다:

| 도구 | 목적 |
|---|---|
| `Read` | 파일 읽기 |
| `Write` | 파일 생성 또는 덮어쓰기 |
| `Edit` | 파일에 대상 지정 변경 적용 |
| `Bash` | 셸 명령 실행 |
| `Glob` | 패턴으로 파일 찾기 |
| `Grep` | 파일 내용 검색 |

일부 명령은 이 목록을 제한합니다 — 예를 들어 `anote review`와 `anote diff`는 `Read`, `Glob`, `Grep`, `Bash`만 허용합니다. 검토는 파일을 작성해서는 안 되기 때문입니다.

## 턴과 압축

각 도구 호출/응답 쌍은 하나의 턴으로 계산됩니다. 에이전트는 `maxTurns`(기본값 30, `anote config set maxTurns <n>` 또는 `.anote.json`으로 설정 가능) 이후 중지됩니다. 긴 세션은 컨텍스트 윈도우를 관리 가능하게 유지하기 위해 `compactAfterMessages`(기본값 40) 이후 압축됩니다.

## 스트리밍

모든 서피스 — CLI, VS Code, 웹, 데스크톱 — 는 동일한 백엔드 엔드포인트(`POST /api/chat/stream`)와 통신하며, 이는 모델의 응답과 도구 활동을 발생하는 대로 SSE를 통해 스트리밍합니다. 최종 답변뿐만 아니라 파일 읽기, 편집, 명령 출력을 실시간으로 볼 수 있습니다.

## 멀티 프로바이더

에이전트 루프는 하나의 모델에 묶여 있지 않습니다. `anote ask --compare`는 동일한 프롬프트를 여러 모델에서 나란히 실행하며, 대부분의 명령에서 `--model`은 구성된 모든 프로바이더(`claude-sonnet-4-6`, `gpt-4.1`, `gemini-2.5-pro`, 또는 로컬 `ollama/<model>`)를 허용합니다.
