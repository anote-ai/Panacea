# Panacea가 작동하는 방식

Panacea는 **에이전트 루프**를 실행합니다: 프롬프트를 읽고, 호출할 도구를 결정하고, 실행하며, 결과를 읽고, 작업이 완료되거나 턴 제한에 도달할 때까지 — 자신의 추론과 수정을 스트리밍하여 다시 제공합니다.

## 도구

기본적으로 Panacea의 에이전트는 다음 도구를 호출할 수 있습니다:

| 도구 | 목적 |
|---|---|
| `Read` | 파일 읽기 |
| `Write` | 파일 생성 또는 덮어쓰기 |
| `Edit` | 파일에 대한 특정 변경 수행 |
| `Bash` | 셸 명령 실행 |
| `Glob` | 패턴으로 파일 찾기 |
| `Grep` | 파일 내용 검색 |

일부 명령은 이 목록을 좁힙니다 — 예를 들어, `anote review` 및 `anote diff`는 리뷰가 파일을 작성하지 않아야 하므로 `Read`, `Glob`, `Grep`, 및 `Bash`만 허용합니다.

## 턴 및 압축

각 도구 호출/응답 쌍은 하나의 턴으로 계산됩니다. 에이전트는 `maxTurns`(기본값 30, `anote config set maxTurns <n>` 또는 `.anote.json`을 통해 구성 가능) 후에 중지합니다. 긴 세션은 `compactAfterMessages`(기본값 40) 이후에 압축되어 컨텍스트 창을 관리 가능하게 유지합니다.

## 스트리밍

모든 인터페이스 — CLI, VS Code, 웹, 데스크탑 — 는 동일한 백엔드 엔드포인트(`POST /api/chat/stream`)와 통신하며, 모델의 응답과 도구 활동을 SSE를 통해 실시간으로 스트리밍합니다. 파일 읽기, 편집 및 명령 출력을 실시간으로 볼 수 있으며, 최종 답변만 보지 않습니다.

## 다중 제공자

에이전트 루프는 하나의 모델에 묶여 있지 않습니다. `anote ask --compare`는 여러 모델에서 동일한 프롬프트를 나란히 실행하며, 대부분의 명령에서 `--model`은 구성된 제공자(`claude-sonnet-4-6`, `gpt-4.1`, `gemini-2.5-pro`, 또는 로컬 `ollama/<model>`)를 수용합니다.
