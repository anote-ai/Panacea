# Как работает Panacea

Panacea выполняет **агентный цикл**: он читает ваш запрос, решает, какие инструменты вызвать, выполняет их, читает результаты и повторяет — передавая вам свои размышления и правки — пока задача не будет выполнена или не будет достигнут лимит поворотов.

## Инструменты

По умолчанию агент Panacea может вызывать:

| Инструмент | Назначение |
|---|---|
| `Read` | Чтение файла |
| `Write` | Создание или перезапись файла |
| `Edit` | Внесение целевого изменения в файл |
| `Bash` | Выполнение команды оболочки |
| `Glob` | Поиск файлов по шаблону |
| `Grep` | Поиск содержимого файлов |

Некоторые команды сужают этот список — `anote review` и `anote diff`, например, разрешают только `Read`, `Glob`, `Grep` и `Bash`, так как обзор не должен записывать файлы.

## Повороты и сжатие

Каждая пара вызов/ответ инструмента считается поворотом. Агент останавливается после `maxTurns` (по умолчанию 30, настраивается через `anote config set maxTurns <n>` или `.anote.json`). Долгие сессии сжимаются после `compactAfterMessages` (по умолчанию 40), чтобы сохранить окно контекста управляемым.

## Потоковая передача

Каждая поверхность — CLI, VS Code, Web, Desktop — общается с одной и той же конечной точкой бэкенда (`POST /api/chat/stream`), которая передает ответ модели и активность инструментов через SSE по мере их выполнения. Вы видите чтение файлов, правки и вывод команд в реальном времени, а не только финальный ответ.

## Мультипровайдер

Цикл агента не привязан к одной модели. `anote ask --compare` выполняет один и тот же запрос одновременно на нескольких моделях, а `--model` в большинстве команд принимает любого настроенного провайдера (`claude-sonnet-4-6`, `gpt-4.1`, `gemini-2.5-pro` или локальный `ollama/<model>`).
