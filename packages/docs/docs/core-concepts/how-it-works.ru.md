# Как работает Panacea

Panacea выполняет **агентный цикл**: читает ваш промпт, решает, какие инструменты вызвать, выполняет их, читает результаты и повторяет — передавая вам своё рассуждение и правки в потоковом режиме — пока задача не будет выполнена или не будет достигнут лимит по количеству ходов.

## Инструменты

По умолчанию агент Panacea может вызывать:

| Инструмент | Назначение |
|---|---|
| `Read` | Прочитать файл |
| `Write` | Создать или перезаписать файл |
| `Edit` | Внести точечное изменение в файл |
| `Bash` | Выполнить команду оболочки |
| `Glob` | Найти файлы по шаблону |
| `Grep` | Искать по содержимому файлов |

Некоторые команды сужают этот список — например, `anote review` и `anote diff` разрешают только `Read`, `Glob`, `Grep` и `Bash`, поскольку проверка не должна записывать файлы.

## Ходы и сжатие

Каждая пара вызов инструмента/ответ считается одним ходом. Агент останавливается после `maxTurns` (по умолчанию 30, настраивается через `anote config set maxTurns <n>` или `.anote.json`). Длинные сессии сжимаются после `compactAfterMessages` (по умолчанию 40), чтобы держать контекстное окно под контролем.

## Потоковая передача

Каждая платформа — CLI, VS Code, веб, десктоп — обращается к одной и той же конечной точке бэкенда (`POST /api/chat/stream`), которая передаёт ответ модели и активность инструментов через SSE по мере их появления. Вы видите чтение файлов, правки и вывод команд в реальном времени, а не только итоговый ответ.

## Мульти-провайдер

Цикл агента не привязан к одной модели. `anote ask --compare` запускает один и тот же промпт на нескольких моделях бок о бок, а `--model` в большинстве команд принимает любого настроенного провайдера (`claude-sonnet-4-6`, `gpt-4.1`, `gemini-2.5-pro` или локальный `ollama/<model>`).
