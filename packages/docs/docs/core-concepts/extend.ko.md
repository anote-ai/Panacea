# Panacea 확장

Panacea의 동작 방식을 사용자 정의하는 두 가지 방법: **CLAW.md**는 지속적인 지침을 제공하고, **hooks**는 도구 호출 주위에서 자신의 명령을 실행하는 데 사용됩니다.

## CLAW.md — 프로젝트 메모리

`CLAW.md`는 Panacea가 프로젝트 컨텍스트를 읽기 위한 마크다운 파일입니다 — 인간이 아닌 에이전트를 위한 README와 같은 개념입니다. `anote init` 명령어는 자동으로 생성되며, 감지된 스택과 검증 명령어(테스트/린트/빌드)로 미리 채워집니다:

```markdown
# CLAW.md

이 파일은 이 리포지토리의 코드 작업 시 Anote AI에 지침을 제공합니다.

## 프로젝트 개요

<!-- 이 프로젝트가 하는 일을 설명하세요 -->

## 스택

TypeScript · Next.js

## 검증

변경이 완료되었다고 고려하기 전에 다음을 실행하세요:

  npm test
  npm run lint

## 작업 합의

- 변경하기 전에 관련 파일을 읽으세요
- 논리를 수정한 후 검증 명령어를 실행하세요
- 변경 사항은 작고 집중적으로 유지하세요
- 새로운 파일을 만드는 것보다 기존 파일을 편집하는 것을 선호하세요
```

자유롭게 편집하세요 — 아키텍처 노트, 규칙 또는 에이전트가 자주 잘못 이해하는 사항을 추가할 수 있습니다. Panacea는 해당 디렉토리의 모든 세션 시작 시 이를 읽습니다.

## Hooks — 도구 호출 주위에서 자신의 명령 실행

Hooks는 각 도구 호출 전(`preToolUse`) 또는 후(`postToolUse`)에 셸 명령어를 실행하며, 이는 `.anote.json`에서 구성됩니다:

```json
{
  "hooks": {
    "preToolUse": ["./scripts/check-tool-policy.sh"],
    "postToolUse": ["npx prettier --write ."]
  }
}
```

**종료 코드 의미:**

| 종료 코드 | 효과 |
|---|---|
| `0` | 허용 — stdout는 정보 메시지로 캡처됨 |
| `2` | 거부 — stdout는 이유로 캡처되어 에이전트에게 표시됨 |
| 그 외의 모든 것 | 경고하지만 허용 |

`preToolUse`를 사용하여 위험한 명령을 차단하거나 실행 전에 정책을 시행하세요; `postToolUse`는 모든 편집 후 자동 포맷팅과 같은 작업에 사용하세요.
