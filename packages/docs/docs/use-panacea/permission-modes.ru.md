# Режимы разрешений

Panacea имеет три режима разрешений, контролирующих, должен ли агент спрашивать перед записью файлов или выполнением команд.

| Режим | Поведение |
|---|---|
| `default` | Подтверждает перед редактированием файлов или выполнением команд, не являющихся только для чтения |
| `acceptEdits` | Автоматически принимает изменения файлов без запроса |
| `bypassPermissions` | Выполняет все без подтверждения — используйте с осторожностью |

Установите его глобально или для конкретного проекта:

```bash
anote config set permissionMode acceptEdits
```

или в `.anote.json`:

```json
{ "permissionMode": "acceptEdits" }
```

## Переопределения для каждой команды

Большинство команд не требуют от вас изменения глобальной конфигурации — они принимают свои собственные флаги для той же идеи:

| Флаг | Доступно в | Эффект |
|---|---|---|
| `--auto` | `fix`, `refactor` | Автоматически принимает изменения только для этого запуска |
| `--dry-run` | `fix`, `docs`, `migrate`, `security`, `perf`, `refactor`, `generate`, `changelog`, `commit`, `review` | Показывает, что произойдет, не записывая ничего |
| `--no-edit` | `ask` | Только для чтения — агент не может изменять файлы, даже если хочет |
| `--yes` | `init` | Пропускает интерактивные запросы, принимает значения по умолчанию |

`anote fix --loop` автоматически подразумевает `acceptEdits`, так как ему нужно продолжать редактирование на протяжении итераций, не останавливаясь, чтобы спрашивать каждый раз.

## Хуки как уровень политики

Для всего более специфичного, чем "спрашивать или не спрашивать" — например, блокировка вызовов `Bash`, которые касаются определенного пути — используйте хук `preToolUse`. См. [Расширьте Panacea](../core-concepts/extend.md).
