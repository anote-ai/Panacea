# Panacea AI コーディングツールチェーン

このレシピでは、PanaceaのAIコーディング体験がCLI、SDK、およびVS Codeを通じてどのように提供されるかを説明します。

## 学べること

- PanaceaにおけるさまざまなAIコーディングのエントリーポイント
- CLI、SDK、およびVS Code拡張が共有バックエンドにどのように関連しているか
- プライベートコード支援のための主要な製品機能
- 実装の詳細を探すためのリポジトリ内の場所

## なぜこれが重要か

Panaceaは、複数のインターフェースを持つ統一された製品として構築されています：

- `anote chat`、コード検索、リポジトリレビューを駆動する**CLI**
- エディタ内AI支援のための**VS Code拡張**
- 他のアプリケーションにPanaceaを埋め込むための**SDK**

これらのインターフェースは、バックエンドとエージェント駆動の推論レイヤーを共有しており、デスクトップ、ウェブ、コードワークフロー全体で製品の一貫性を保っています。

## 主要なPanaceaファイル

| ファイル | 重要な理由 |
|---|---|
| `Panacea/packages/cli` | 開発者ワークフローのためのTypeScript CLI実装 |
| `Panacea/packages/vscode` | VS Code拡張およびチャット統合 |
| `Panacea/packages/sdk` | プログラムによるアクセスのためのTypeScript SDK |
| `Panacea/packages/backend` | すべてのUIおよびCLIインタラクションを支える共有バックエンドサービス |

## 仕組み

- コーディングユーザーのアクションはCLI、SDK、またはVS Code拡張から始まります。
- リクエストはPanaceaのバックエンドAPIに送信されます。
- バックエンドはエージェントオーケストレーションとモデルプロバイダーを使用して、コードを意識した回答を生成します。
- レスポンスは同じインターフェースで返され、コードの提案、説明、または修正が含まれます。

## 便利な製品機能

- **CLI**: `anote chat`、リポジトリ検索、コードレビュー、コード生成、および埋め込みによる支援。
- **VS Code**: インラインチャット、差分プレビュー、コードアクション、およびストリーミングレスポンス。
- **SDK**: Panacea APIのクライアントラッパーで、カスタム統合を可能にします。

## ローカルで実行する

ワークスペースのルートから（`anote/panacea`）:

```bash
cd Panacea
cp packages/backend/.env.example packages/backend/.env
docker compose up --build
```

これにより、共有バックエンドおよびフロントエンドサービスが起動します。

別のターミナルで、CLIパッケージを実行します：

```bash
cd Panacea/packages/cli
npm install
npm run dev
```

これで、CLIをローカルで使用するか、`npm run build`でビルドできます。

VS Codeの開発のために、VS Codeで`Panacea/packages/vscode`を開き、デバッガーで拡張を起動します。
